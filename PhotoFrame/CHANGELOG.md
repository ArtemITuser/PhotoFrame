# PhotoFrame — Список изменений

## v1.2.1.0 (build 52) — 11.07.2026 12:37
(© Ochkin Artyom, 2026)

### Ночной режим (автоотключение рамки)
- Перенесён из вкладки «Система» на вкладку **«Питание»** — логически это
  режим энергопотребления/показа, а не системная интеграция.
- Проверена корректность входа/выхода: ручное расписание учитывает переход
  через полночь (`From > To`), режим «закат→рассвет» и «умный подсчёт»
  сравниваются по UTC-корректному локальному времени; событие
  `ShouldBeActiveChanged` вызывается только при фактической смене
  состояния (не на каждый тик таймера) — регрессий не найдено.
- `AutoOffScheduler.Start()` сделан идемпотентным: повторный вызов без
  предшествующего `Stop()` больше не плодит дублирующиеся подписки на
  `DispatcherTimer.Tick` (защитный рефакторинг, ранее это не проявлялось
  только благодаря тому, что `Start()` вызывался один раз при старте).

### Темы: поля ввода и полосы прокрутки
- **`TextBox`** и **`ScrollBar`** ранее не имели собственного стиля в
  `CommonStyles.xaml` и рендерились системными (белое поле ввода, серый
  скроллбар) независимо от выбранной темы — в тёмной теме это выглядело
  как светлые "дыры" в интерфейсе. Теперь оба используют
  `InputBgBrush`/`InputFgBrush`/`InputBorderBrush`/`Surface2Brush`/
  `AccentBrush` текущей темы (Light/Dark/Aero7/Aero7 Dark) — согласовано
  с уже существовавшим стилем `ComboBox`.

### Live Tiles — аудит и кадрирование фото
- Проверены все 4 размера (Small 71×71, Medium 150×150, Wide 310×150,
  Large 310×310) — привязки и брендинг присутствуют у всех.
- **Новое**: фото для плиток больше не передаётся "как есть" с
  `hint-crop="none"` на разных пропорциях (это давало непредсказуемую
  обрезку/пустые поля). Теперь генерируются две кадрированные копии —
  квадратная (Small/Medium/Large) и широкая 2.07:1 (Wide) — с управляемой
  **дистанцией фото** (`TilePhotoDistance`: Крупный план / Сбалансированно
  / Целиком), настраиваемой в разделе Live Tiles. Временные файлы
  перезаписываются на месте — не накапливаются во временной папке.

### Автозагрузка и регистрация скринсейвера — корректный EXE + обработчики ошибок
- **Баг**: `SetAutostart` использовал
  `Assembly.GetExecutingAssembly().Location` — для однофайловой
  (`PublishSingleFile`) публикации это пустая строка, а для обычной
  публикации .NET 5+ указывает на управляемую `.dll`, а не на apphost
  `.exe` (Windows не может запустить `.dll` через `ShellExecute`). Для
  ClickOnce дополнительно — путь к `.exe` меняется при КАЖДОМ
  автообновлении (версионированный кеш-каталог), поэтому ранее записанный
  путь в `HKCU\Run` неизбежно ломался после следующего обновления.
- **Исправление**: `ResolveHostExecutablePath()` — для ClickOnce ищет
  стабильный ярлык `*.appref-ms` в Меню Пуск (ClickOnce сам поддерживает
  его актуальным), иначе использует `Environment.ProcessPath` (корректно
  работает для single-file/self-contained/framework-dependent публикации).
- **MSIX**: автозапуск для MSIX-пакета объявляется в
  `Package.appxmanifest` (`windows.startupTask`) — при обнаружении
  package identity (`GetCurrentPackageFullName`) `SetAutostart` больше не
  трогает реестр и сообщает пользователю о правильном месте включения
  (Диспетчер задач → «Автозагрузка»).
- **Обработчики ошибок** добавлены во все точки: `SetAutostart` и
  `RegisterScreensaver` теперь возвращают конкретную причину отказа
  (`UnauthorizedAccessException`, `SecurityException`, занятый файл,
  недоступный раздел реестра) вместо молчаливого проглатывания —
  `OnApply` в настройках показывает ошибку автозагрузки пользователю.
- Три места `new HttpClient(...)` в `SystemIntegration` заменены на общий
  статический клиент ещё в build 51 — здесь дополнительно ревизия
  подтвердила отсутствие регрессий.

### MSIX / MSIXBUNDLE
- Добавлен `Package/Package.appxmanifest` — манифест упаковки (Identity,
  VisualElements всех размеров плиток, `windows.startupTask`,
  `broadFileSystemAccess` для доступа к источникам фото на любых дисках).
- Сгенерированы placeholder-ассеты (`Package/Assets/*.png`, синий фон
  `#2F7FCC` + логотип из `AppIcon.ico`) — готовы к замене на финальный
  дизайн через Assets Generator в Visual Studio.
- `Package/README_MSIX.md` — пошаговая инструкция сборки `.msix`/
  `.msixbundle` через Visual Studio (`.wapproj`) и через командную строку
  (`makeappx`/`signtool`), включая различия автозапуска/Live-Tile
  брендинга между MSIX и InnoSetup/ClickOnce.

### Служба обновлений — проверка по расписанию
- Ранее проверка обновлений была только ручной (кнопка в разделе «О
  программе»). Теперь `AppSettings.AutoCheckUpdatesEnabled` +
  `UpdateCheckPeriodDays` (1–30 дней, по умолчанию 3) позволяют службе
  обновлений проверять новую версию автоматически в фоне при запуске —
  но не чаще заданного периода (`LastUpdateCheckUtc` — таймстемп
  последней УСПЕШНОЙ проверки; при недоступности сети таймстемп не
  обновляется, следующая попытка — при следующем запуске). При
  обнаружении новой версии показывается всплывающее уведомление трея со
  ссылкой на страницу релизов, без блокирующих диалогов.
- Настройки автопроверки перенесены в тот же раздел, что и
  `UpdateMirrorUrl` (зеркало/своя ссылка) — единая секция «Проверка
  обновлений» в «О программе».

### Редактируемые поля времени
- Слайдеры задержки скринсейвера, отключения монитора, перехода в сон и
  расписания ночного режима (от/до) теперь сопровождаются полем `TextBox`
  для ручного ввода значения — не только перетаскиванием. Общий парсер
  `TryParseClampedInt` переиспользуется для минут (0 = не управлять) и
  периода автопроверки в днях; отдельный `TryParseTimeOfDay` понимает
  форматы `23:00`, `23.00`, `2300` и `23` для полей «от/до». Enter в поле
  переносит фокус (штатно вызывает фиксацию значения), некорректный ввод
  откатывается к текущему значению слайдера.

### Рефакторинг
- Единая логика редактируемых слайдер+поле пар вместо дублирования по
  каждому отдельному полю.
- `App.ApplyUiMode`/`ApplyTheme` синхронизированы через общий
  `RefreshAeroOverlay()` (см. build 51) — подтверждено отсутствие
  регрессий при добавлении новых настроек.

### Библиотеки/зависимости
- `TargetFramework` оставлен `net8.0-windows10.0.19041.0` (LTS,
  поддерживается) — в этом окружении нет доступа к NuGet для сверки
  актуальных версий пакетов (`System.Management`, `Microsoft.CSharp`);
  рекомендуется перед публикацией выполнить `dotnet list package
  --outdated` локально и обновить при необходимости. Версии в `.csproj`
  не изменялись, чтобы не вносить непроверенные в этом окружении
  зависимости.

## v1.2.0.9 (build 51) — 04.07.2026

Продолжение линии v1.2.0.3 (build 46). Ветка v1.4.0.0 (build 50) закрыта;
её функциональность повторно применена к базе build 46 и дополнена ниже.
(© Ochkin Artyom, 2026)

### Повторно применённые исправления/функции (из ветки build 50)
- P/Invoke: все `DllImport` → `LibraryImport` (source-generated маршалинг)
- `PreventSleep` проверяет результат `SetThreadExecutionState`
- **Баг счётчика**: `PlaylistManager.PlaybackPosition` вместо `CurrentIndex`
  для отображения — счётчик и Start/End-индикаторы корректны в
  Shuffle/TrueRandom. *Проверено повторно в build 51 — регрессий нет.*
- Центрирование тулбара навигации: `Grid.ColumnSpan="3"` — истинный центр
  окна. Счётчик кадров (`CounterBadge`) центрирован независимо
  (`HorizontalAlignment="Center"` на `RootGrid`). *Проверено в build 51.*
- Иконки экспорта: `&#xE896;`/`&#xE8A1;` → `&#xE8E5;`/`&#xE9D9;`
  (семантически корректные глифы для «список»/«таблица»)
- Win7/8: предложение установить Segoe MDL2 Assets, без повторов на
  Win10/11, с опцией «не предлагать больше»
- «О программе»: расход ОЗУ/кеша + кнопка безопасной очистки
- Live Tiles: независимая частота обновления + закрепление на начальном экране
- Скринсейвер из трея: проверка простоя через `GetLastInputInfo`
- **Автоотключение рамки по расписанию** — три режима: умный подсчёт
  использования, ручное расписание от/до, закат→рассвет (геолокация по IP
  или вручную заданные координаты)
- **Просмотр USB-устройств**: иерархический браузер ФС Lumia (Windows 10
  Mobile)/Android/iOS с импортом фото в источники
- GPS → название места на русском (OpenStreetMap Nominatim, опционально)
- **Зеркало обновлений**: настраиваемый `UpdateMirrorUrl` вместо
  жёстко заданного GitHub API

### Новое в build 51
- **Импорт списка папок** из ранее выгруженного `.txt`/`.csv` (обратная
  операция к «Выгрузка списка»): понимает формат дерева (`📁 путь` / `• файл`)
  и плоский список путей; для CSV — колонку «Папка» либо каталог из «Путь».
  Пропущенные (не найденные на диске) записи не прерывают импорт и
  отображаются в итоговой сводке.
- **MDL2-глифы импорта** `&#xE896;` (Download) / `&#xE8A1;` (OpenFile) —
  ранее использовавшиеся (и признанные неверными) для экспорта глифы,
  теперь применены по назначению для импорта.
- **Aero7 Dark** — тёмный вариант оформления Aero7 (`AeroDarkTheme.xaml`),
  подключается автоматически при `UiMode=Aero7` и тёмной теме (вручную или
  по системной). Раньше Aero7 всегда рендерился «светлым стеклом»
  независимо от выбранной темы — переключение Тёмная/Светлая на Aero7
  не имело эффекта. `App.ApplyUiMode`/`ApplyTheme` теперь синхронизированы
  через общий `RefreshAeroOverlay()`.
- **Аудит и исправление корректности сборки мусора / управления ресурсами**:
  - `SystemIntegration`: три места `using var http = new HttpClient(...)`
    заменены на общий статический `HttpClient` + `CancellationTokenSource`
    на вызов (устраняет повторное открытие/закрытие сокетов и связанный с
    этим риск истощения портов при частых проверках обновлений/геолокации).
  - `DeviceBrowserService`: COM-объекты Shell.Application/Folder/FolderItem
    (поздне-связанные `dynamic`) теперь явно освобождаются через
    `Marshal.FinalReleaseComObject` во всех методах и в рекурсивном обходе
    дерева устройства — ранее RCW жили до финализации GC.
  - Проверено: `LoadBitmapSafe`/превью в `SettingsWindow` уже используют
    `BitmapCacheOption.OnLoad` + `Freeze()` — замечаний нет.
  - Проверено: таймеры (`_slideTimer`, `_hideTimer`, `_counterTimer`,
    `_idleCheckTimer`, `AutoOffScheduler`) и статическое событие
    `App.ThemeChanged` корректно отписываются в `MainWindow.OnClosing` —
    замечаний нет.
  - Исправлен потенциальный баг подбора словаря темы в `App.ApplyTheme`:
    цикл поиска ресурса, оканчивающегося на `"Theme.xaml"`, мог случайно
    совпасть с `AeroTheme.xaml`/`AeroDarkTheme.xaml`; теперь эти два
    словаря явно исключены из совпадения.
  - См. также `AUDIT.md` — полный отчёт.
- Версия и копирайт обновлены во всех проектных файлах
  (`PhotoFrame.csproj`, `Installer.iss`, `README_ANS.md`).

## v1.4.0.0 (build 50) — 2026 *(ветка закрыта, см. выше)*

Откат к базе v1.2.0.3 (build 46) с повторным применением ранее согласованных
исправлений и добавлением нового функционала.

### Исправления
- P/Invoke: все `DllImport` → `LibraryImport` (source-generated маршалинг)
- `PreventSleep` проверяет результат `SetThreadExecutionState`
- **Баг счётчика**: `PlaylistManager.CurrentIndex` (индекс в исходном списке)
  использовался вместо позиции в очереди воспроизведения — счётчик и
  Start/End-индикаторы были неверны в режимах Shuffle/TrueRandom.
  Добавлены `PlaybackPosition`, `IsAtStart`, `IsAtEnd`
- Центрирование тулбара: навигация теперь `Grid.ColumnSpan="3"` — истинный
  центр окна вместо центра средней колонки (было смещение ≈13px)
- Иконки экспорта: `&#xE896;`/`&#xE8A1;` → `&#xE8E5;`/`&#xE9D9;`
  (семантически корректные глифы для «список»/«таблица»)

### Новое
- **Win7/8**: предложение установить Segoe MDL2 Assets с archive.org,
  без повторов на Win10/11, с опцией «не предлагать больше»
- **Стоп-лист путей**: закрытие баннера ошибки крестиком больше не
  показывает его повторно при следующих запусках
- **О программе**: расход ОЗУ/кеша + кнопка безопасной очистки
- **Live Tiles**: независимая частота обновления картинки + кнопка
  закрепления плитки на начальном экране (Win10/11)
- **Скринсейвер из трея**: истинная проверка простоя системы через
  `GetLastInputInfo`, запуск слайдшоу только при реальном бездействии
- **Автоотключение рамки по расписанию** — три режима: умный подсчёт
  использования, ручное расписание от/до, закат→рассвет (авто по
  геолокации или вручную заданным координатам)
- **Просмотр USB-устройств**: иерархический браузер файловой системы
  Lumia (Windows 10 Mobile) / Android / iOS с импортом фото в источники
- **GPS → название места на русском**: опциональное обратное
  геокодирование через OpenStreetMap Nominatim
- **Зеркало обновлений**: настраиваемый URL для проверки версий вместо
  жёстко заданного GitHub API
